## 📦 [Phase 2] Order System (Core Business Logic)

음식 배달 서비스의 핵심인 **주문(Order) 처리 시스템**입니다. 고객의 주문 생성부터 점주의 접수, 배달 기사의 배달 완료까지의 전체 생명주기(Lifecycle)를 관리하며, 데이터 무결성과 보안에 중점을 두고 설계되었습니다.

### 1. 핵심 기술 구현 (Key Implementations)

#### 📸 데이터 스냅샷 패턴 (Snapshot Pattern)
메뉴의 가격이나 구성은 수시로 변경될 수 있습니다. 과거의 주문 이력이 현재의 메뉴 변경사항에 영향을 받지 않도록 **주문 시점의 데이터를 동결(Freeze)**하여 저장합니다.
* **구현 방식**: `Order`와 `Dish`를 직접 연결하지 않고, `OrderItem`이라는 별도 엔티티를 두어 주문 당시의 `메뉴명`, `가격`, `옵션(JSON)`을 깊은 복사(Deep Copy)하여 저장합니다.



#### 🛡️ 금액 변조 방지 보안 로직 (Security Logic)
클라이언트(프론트엔드)에서 계산된 총액이나 옵션 가격을 절대 신뢰하지 않습니다.
* **검증 프로세스**: 요청받은 메뉴와 옵션 ID를 기반으로 **서버가 DB에서 직접 가격을 조회하여 재계산**합니다.
* **효과**: 악의적인 사용자가 API 요청을 조작하여 가격을 `0원`이나 `마이너스`로 보내는 공격을 원천 차단했습니다.

#### ⚛️ 트랜잭션 관리 (ACID Transaction)
주문 생성은 `OrderItem` 생성과 `Order` 생성이 동시에 이루어져야 하는 원자적(Atomic) 작업입니다.
* **구현**: `DataSource`의 `QueryRunner`를 활용한 트랜잭션을 적용하여, 중간에 하나라도 실패할 경우 **전체 로직을 롤백(Rollback)** 처리하여 데이터 정합성을 보장합니다.

#### 🚦 상태 머신 및 권한 관리 (State Machine & RBAC)
주문 상태 변경은 엄격한 권한 체크를 통과해야 합니다.

| 상태 (Status) | 설명 | 변경 가능 역할 (Role) | 비고 |
| :--- | :--- | :--- | :--- |
| **Pending** | 주문 대기 | Client (생성) | 점주의 수락을 기다리는 초기 상태 |
| **Cooking** | 조리 중 | Owner | 점주가 주문을 수락함 |
| **Cooked** | 조리 완료 | Owner | 조리가 끝나고 배달 기사를 호출함 |
| **PickedUp** | 배달 중 | Delivery | 기사가 배차를 수락하고 음식을 픽업함 |
| **Delivered** | 배달 완료 | Delivery | 고객에게 음식 전달 완료 |

### 2. API Endpoints

#### 📦 Order (주문)
| Method | URI | Auth | Description |
| :--- | :--- | :--- | :--- |
| `POST` | `/orders` | **Client** | 장바구니 결제 및 주문 생성 (트랜잭션 적용) |
| `GET` | `/orders` | **Any** | 내 주문 목록 조회 (Role에 따라 필터링되어 응답) |
| `GET` | `/orders/:id` | **Any** | 주문 상세 조회 (본인 관련 주문만 접근 허용) |
| `PATCH` | `/orders/:id` | **Owner, Delivery** | 주문 상태 변경 (Pending -> Cooking -> ... -> Delivered) |

### 3. 주요 로직 상세 (Code Highlights)

#### 주문 상세 조회 권한 분기 (`getOrderById`)
하나의 API로 모든 유저 타입을 처리하되, 내부적으로 **데이터 격리(Data Isolation)**를 구현했습니다.

```typescript
// Role별 접근 제어 예시
switch (user.role) {
  case Role.CLIENT:
    if (order.customerId !== user.id) throw new ForbiddenException(); // 내 주문만
    break;
  case Role.OWNER:
    if (order.restaurant.ownerId !== user.id) throw new ForbiddenException(); // 내 가게 주문만
    break;
  case Role.DELIVERY:
    // 조리 완료된(배차 가능) 주문이거나, 내가 배차받은 주문만
    if (order.status !== 'Cooked' && order.driverId !== user.id) throw new ForbiddenException();
    break;
}
```

#### 옵션 가격 서버 사이드 검증
```typescript
// 클라이언트가 보낸 'itemDto.options'의 가격(extra)을 무시하고
// DB에 저장된 'dish.options'의 가격을 찾아 계산
const validOption = dish.options?.find((o) => o.name === userOption.name);
if (validOption) {
  dishTotal += validOption.extra; // ✅ Secure Calculation
}
```

### 4. Database Schema (ERD)

* **Order**: `total`(총액), `status`(상태), `restaurantId`, `customerId`, `driverId`
* **OrderItem**: `orderId`, `dishId`(Set Null), `dishName`(Snapshot), `options`(JSON Snapshot)
