## 📡 [Phase 4] Real-time System (Socket.io & Gateway)

기존의 단순 REST API 구조에 **WebSockets (Socket.io)**를 결합하여 실시간 주문 알림 및 배달 위치 추적 기능을 구현했습니다. 데이터의 영속성이 필요한 작업은 REST API로, 실시간성이 중요한 작업은 Socket으로 분리하여 서버 부하를 최소화했습니다.

### 1. 아키텍처 설계 (Architecture Design)

#### 🔄 Hybrid Architecture (REST + Socket)
* **REST API**: 데이터의 생성(Create), 수정(Update), 조회(Read)와 같은 **상태 변경(State Change)**을 담당하며 DB 트랜잭션을 보장합니다.
* **Socket Gateway**: 상태 변경에 따른 **이벤트 전파(Event Propagation)**와 휘발성 데이터(GPS 좌표)의 **실시간 중계(Relay)**를 담당합니다.

#### 📍 실시간 위치 추적 (Real-time Location Relay)
기존 DB 스키마를 변경하지 않고 실시간 위치 추적을 구현하기 위해 **In-memory Relay** 방식을 채택했습니다.
* **Flow**: `Driver(Client)` ➡ `Socket Gateway(Server)` ➡ `Customer(Client)`
* **특징**: 배달원의 GPS 좌표는 DB에 저장되지 않고, 소켓 서버를 통해 고객에게 즉시 전달되어 지도에 표시됩니다. 이를 통해 불필요한 DB I/O 비용을 절감했습니다.

### 2. 주요 구현 로직 (Key Implementations)

#### 트랜잭션과 알림의 분리 (Transaction Safety)
주문 생성(`createOrder`) 시, **DB 트랜잭션이 완벽하게 커밋된 후**에만 소켓 알림을 발송합니다. 이를 통해 DB에는 데이터가 없는데 알림이 발송되는 '유령 알림' 현상을 방지했습니다.

```typescript
// OrderService.ts
const order = await this.dataSource.transaction(async (manager) => {
  // 1. 주문 아이템 스냅샷 저장
  // 2. 주문정보 저장 (Pending 상태)
  return newOrder;
}); 
// [트랜잭션 성공 후 실행]
this.eventsGateway.server.to(ownerRoom).emit('newPendingOrder', { ... });
```

#### 동적 룸 관리 (Dynamic Room Management)
유저의 역할(Role)과 주문(Order) 상태에 따라 소켓 룸(Room)을 동적으로 분리하여, 필요한 대상에게만 메시지를 전송합니다.
* **User Room**: `Owner:1` (본인 가게 주문 알림용)
* **Order Room**: `order:10` (해당 주문의 상태 변경 및 위치 공유용 - 고객/점주/배달원 참여)

### 3. Socket Event API Specification

클라이언트(Frontend)와의 통신을 위한 소켓 이벤트 명세입니다.

#### 📤 Client ➡ Server (Emit)

| Event Name | Payload | Description |
| :--- | :--- | :--- |
| `joinUserRoom` | `{ userId, role }` | 로그인 직후 본인의 고유 채널 입장 |
| `joinOrderRoom` | `{ orderId }` | 주문 상세 진입 시 해당 주문 채널 입장 |
| `updateDriverLocation` | `{ orderId, lat, lng }` | (배달원) 실시간 GPS 좌표 전송 |

#### 📥 Server ➡ Client (On)

| Event Name | Target | Data | Description |
| :--- | :--- | :--- | :--- |
| `newPendingOrder` | Owner | `{ orderId, total }` | 새 주문이 들어왔음을 점주에게 알림 |
| `orderUpdate` | Order Room | `{ status, driverId }` | 주문 상태 변경 알림 (조리중, 배달중 등) |
| `driverLocation` | Order Room | `{ lat, lng }` | (고객) 배달원의 현재 위치 수신 |
| `newCookedOrder` | Delivery | `{ restaurantName }` | (배달원) 조리 완료된 주문 배차 요청 알림 |
