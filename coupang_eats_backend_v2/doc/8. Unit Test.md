## 🧪 [Phase 6] Unit Testing (Code Reliability)

서비스의 안정성을 보장하고 리팩토링 과정에서의 사이드 이펙트를 방지하기 위해 **Jest**를 활용한 단위 테스트(Unit Test)를 구축했습니다. 외부 의존성(Database, External API)을 완벽하게 격리(Isolation)하기 위해 **Mocking** 기법을 적용했습니다.

### 1. 테스트 전략 (Testing Strategy)

* **Isolation (격리)**: `Repository`, `DataSource`, `SocketGateway` 등 모든 외부 의존성을 `Mock Object`로 대체하여, 오직 **Service Layer의 비즈니스 로직**만을 검증했습니다.
* **Edge Case Coverage (예외 처리)**: 정상 동작(Success)뿐만 아니라, 권한 없음(Forbidden), 데이터 없음(NotFound), 중복 발생(Conflict) 등 다양한 실패 시나리오를 꼼꼼하게 테스트했습니다.
* **Transaction Safety**: `OrderService`와 같이 트랜잭션이 필수적인 로직은 `QueryRunner`와 `EntityManager`를 Mocking하여 원자성(Atomicity) 로직이 호출되는지 검증했습니다.
* **Time Manipulation**: 스케줄러(Cron) 테스트 시 `jest.useFakeTimers()`를 사용하여 시스템 시간을 조작, 특정 시점의 로직 실행을 정확히 테스트했습니다.

### 3. 기술적 하이라이트 (Technical Highlights)

#### 🛠️ Transaction Mocking (복잡한 트랜잭션 로직 테스트)
`OrderService`에서 `dataSource.transaction`을 테스트하기 위해 콜백 실행 흐름을 Mocking했습니다.

```typescript
// DataSource Mocking 예시
const mockDataSource = {
  transaction: jest.fn().mockImplementation(async (cb) => {
    // 트랜잭션 콜백을 강제로 실행하고, Mock Manager를 주입
    return cb(mockEntityManager);
  }),
};
```

#### ⏳ Time Mocking (스케줄러 테스트)
`OrderCronService`가 "어제" 날짜를 제대로 계산하는지 확인하기 위해 Jest의 Fake Timer를 사용했습니다.

```typescript
// 시스템 시간을 2024-01-02로 고정
jest.useFakeTimers();
jest.setSystemTime(new Date('2024-01-02T04:00:00.000Z'));

// 테스트 실행 후 검증
expect(repository.delete).toHaveBeenCalledWith({
  status: OrderStatus.Pending, // 누락된 상태 조건 추가
  createdAt: LessThan(new Date('2024-01-01T04:00:00.000Z')), // 정확히 24시간 전
});
```

### 4. 테스트 실행 방법 (How to Run)

프로젝트 루트에서 다음 명령어를 통해 전체 또는 특정 모듈의 테스트를 수행할 수 있습니다.

```bash
# 전체 유닛 테스트 실행 (All Tests)
npm run test

# 특정 파일만 테스트 (Specific Module)
npm test -- order.service
npm test -- auth.service

# 테스트 커버리지 확인 (Coverage Report)
npm run test:cov
```
