## 🔍 Detailed Review & Technical Decisions

### 1. Order Service Test (Critical Bug Fix)
기존 로직은 `findByIds`를 사용하여 메뉴의 옵션(`DishOptions`)을 로드하지 못하는 치명적인 버그가 있었습니다. 이를 해결하기 위해 `findManyWithOmitNotJoinedProps`로 로직을 변경했고, 테스트 코드도 이에 맞춰 수정했습니다.

- **Mock 변경:** `dishRepository.findManyWithOmitNotJoinedProps` Mocking.
- **검증 포인트:** 메서드 호출 시 `{ options: true }` 인자가 정확히 전달되는지 확인하여 가격 계산 로직이 정상 작동함을 보장합니다.

```typescript
// src/modules/order/order.service.spec.ts
expect(dishRepo.findManyWithOmitNotJoinedProps).toHaveBeenCalledWith(
  { id: In(dishIds) },
  { options: true }, // ✅ 핵심 검증: 옵션 데이터 로드 확인
);
```

### 2. Review Service Test (Optimization & Logic)
리뷰 작성 및 수정 시 불필요한 식당 조회 쿼리를 제거하고 `Join`을 활용하도록 최적화했습니다. 또한, **1주문 1리뷰** 정책을 위해 중복 검사 로직이 추가되었습니다.

- **Mock 변경:** `findByIdOrThrow` 제거 → `findOneWithOmitNotJoinedPropsOrThrow` 사용.
- **Test Case 추가:**
  - **Duplicate Check:** 이미 리뷰가 존재할 경우 `ConflictException` 발생 여부 테스트.
  - **Relation Load:** 주문 조회 시 `restaurant` 관계가 로드되는지 검증.

### 3. User Service Test (Cache Consistency)
유저 정보 수정(`updateUser`) 기능이 추가되면서, 데이터 정합성을 위해 Redis 캐시를 삭제하는 로직이 포함되었습니다.

- **검증 포인트:**
  - 비밀번호 변경 시 `HashService.hash` 호출 여부.
  - **핵심:** 정보 수정 후 `cacheService.del(key)`가 반드시 호출되는지 확인하여 **Stale Data** 문제를 방지.

### 4. Dish & Restaurant Service Test (Missing Coverage)
기존 코드에는 `updateDish`, `updateRestaurant` 메서드는 구현되어 있었으나, 이에 대한 테스트 코드가 전무했습니다.

- **Action:**
  - 각 서비스의 `update` 메서드에 대한 성공/실패(권한 없음, 리소스 없음) 케이스를 모두 작성.
  - Repository Mock에 `create`(병합용) 메서드 정의 추가.
  - **Result:** 핵심 비즈니스 로직의 테스트 커버리지 100% 달성.

### 5. Auth Service Test (Dependency Injection)
회원가입/로그인 로직 고도화로 인해 `CacheService`(이메일 인증 토큰), `NotificationService`(환영 메일) 의존성이 추가되었습니다.

- **Resolution:** 테스트 모듈(`TestingModule`)에 누락된 Provider를 Mock 객체로 주입하여 "Nest can't resolve dependencies" 에러를 해결했습니다.
