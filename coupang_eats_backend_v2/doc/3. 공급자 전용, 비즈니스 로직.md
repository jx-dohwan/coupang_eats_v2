# 🚀 Feature Implementation: Provider Service (Supply Side)

이 섹션은 플랫폼의 공급자(Provider) 측면인 **카테고리(Category)**, **식당(Restaurant)**, **메뉴(Dish)** 기능을 구현한 내용을 다룹니다.
점주(Owner)가 여러 식당과 메뉴를 관리하고, 고객이 이를 조회할 수 있는 핵심 비즈니스 로직이 포함되어 있습니다.

## 1. 변경된 요구사항 및 모델링 (Updated Requirements)

초기 기획과 달리 확장성을 위해 **점주(Owner)와 식당(Restaurant)의 관계를 1:N으로 변경**하였습니다. 이제 한 명의 점주가 프랜차이즈처럼 여러 개의 식당을 소유하고 관리할 수 있습니다.

### 1.1 사용자 역할 및 기능
* **Owner (점주)**
    * **식당 관리**: 자신의 식당을 여러 개 등록(`create`)하고 조회(`read`)할 수 있습니다.
    * **메뉴 관리**: 본인이 소유한 식당에 메뉴를 추가하거나 삭제할 수 있습니다.
    * **보안**: 타인의 식당 정보나 메뉴를 수정/삭제할 수 없도록 소유권 검증 로직이 적용됩니다.
* **Customer (고객)**
    * 전체 식당 목록을 페이지네이션(`pagination`)으로 조회할 수 있습니다.
    * 카테고리별(`categoryId`) 필터링이 가능합니다.

### 1.2 데이터베이스 스키마 변경 (Schema Updates)
비즈니스 로직 변경에 따라 `Restaurant` 테이블과 관계가 아래와 같이 재정의되었습니다.

* **Restaurant Table**
    * `id` (PK): UUID (BaseEntity 상속)
    * `ownerId` (FK): **User(Owner)와 N:1 관계** (기존 1:1에서 변경됨)
    * `categoryId` (FK): Category와 N:1 관계 (Category 삭제 시 `Set Null`)
    * `minimumPrice`: 오타 수정 (`minmumPrice` -> `minimumPrice`)
    * `promotedUntil`: 오타 수정 (`promotedUnitil` -> `promotedUntil`)

## 3. 핵심 구현 로직 (Implementation Details)

### ✅ Generic Repository Pattern 적용
반복되는 CRUD 작업을 줄이고 타입 안정성을 확보하기 위해 `GenericTypeOrmRepository`를 구현하여 사용했습니다.
* `paginate()`: 표준화된 페이지네이션 응답 처리
* `findByIdOrThrow()`: 조회 실패 시 자동 404 예외 처리

### ✅ 보안 및 권한 검증 (Security & RBAC)
단순히 역할(Role)만 확인하는 것이 아니라, 리소스의 소유권을 확인하는 **2차 검증 로직**을 Service Layer에 구현했습니다.

```typescript
// 예시: 메뉴 삭제 시 소유권 검증
async deleteDish(owner: User, dishId: string) {
  // 1. 메뉴와 식당 정보를 Join해서 조회
  const dish = await this.dishRepository.findOneWithRelations({ id: dishId }, { restaurant: true });

  // 2. 요청한 유저가 해당 식당의 주인인지 확인 (Logic Guard)
  if (dish.restaurant.ownerId !== owner.id) {
    throw new ForbiddenException('You cannot delete this dish');
  }
  
  // 3. 삭제 진행
  await this.dishRepository.softDelete(dishId);
}
```

### ✅ 데이터 무결성 정책 (Cascade Policy)
* **Category 삭제 시**: 연결된 식당의 `categoryId`를 `NULL`로 설정하여 식당 데이터는 보존 (`onDelete: SET NULL`).
* **Restaurant 삭제 시**: 연결된 메뉴(Dish)들은 고아 데이터가 되므로 자동 삭제 (`onDelete: CASCADE`).
