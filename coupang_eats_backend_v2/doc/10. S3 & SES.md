# ☁️ AWS Core Module & Authentication System

본 프로젝트는 **AWS S3**를 활용한 이미지 업로드와 **AWS SES** 이메일 인증을 사용합니다.  
배포 환경(ECS)에서는 버킷이 **비공개**이고, 조회는 **CloudFront OAC (`AWS_CDN_URL`)** 로 합니다.

> 인프라 맞춤 변경 상세: [14. Infra Sync.md](./14.%20Infra%20Sync.md)

## 주요 기능

### 1. AwsModule
* **S3:** 식당·메뉴·카테고리·프로필 이미지 (`uuid` 파일명)
* **CloudFront:** `AWS_CDN_URL`이 있으면 공개 URL을 CDN 기준으로 반환
* **SES:** 회원가입 인증 메일
* **Keyless:** Access Key 없이 ECS Task Role / 로컬 자격증명

### 2. Email Verification Flow
1. 회원가입 → `verified: false` + 토큰(UUID)
2. Redis `email-verify:{token}` (TTL 5분)
3. SES로 인증 링크 발송
4. 링크 클릭 → 계정 활성화 + 토큰 삭제

## 환경 변수

```bash
AWS_REGION=ap-northeast-2
AWS_S3_BUCKET_NAME=coupang-eats-dev-storage
AWS_CDN_URL=https://xxxxxxxx.cloudfront.net   # ECS 필수, 로컬은 비워도 됨
AWS_SES_SENDER_EMAIL=jx7789@naver.com
```

예제 파일: `dotenv/.env.example`

### URL 생성 규칙 (`AwsS3Service`)

```
업로드 → key = {folder}/{uuid}{ext}
  AWS_CDN_URL 있음 → {CDN_URL}/{key}
  없음 (로컬)     → https://{bucket}.s3.{region}.amazonaws.com/{key}
```

인프라에서 S3 Public Access는 차단되므로 **배포 환경에서는 `AWS_CDN_URL`이 필수**입니다.

### IAM (요약)

| 주체 | 권한 |
|------|------|
| ECS Task Role | 스토리지 버킷 List/Get/Put/Delete + SES Send (인프라에서 스코프) |
| 로컬 | `aws configure` 또는 환경변수 Access Key |

버킷 ARN 예: `arn:aws:s3:::coupang-eats-dev-storage` / `.../*`

## 로컬 개발

Keyless이므로 코드에 Access Key가 없습니다.

```bash
aws configure   # region: ap-northeast-2
# 또는
export AWS_ACCESS_KEY_ID=...
export AWS_SECRET_ACCESS_KEY=...
npm run start:dev
```

## 트러블슈팅

| 증상 | 원인 | 해결 |
|------|------|------|
| `CredentialsProviderError` | 로컬 자격증명 없음 | `aws configure` |
| `MessageRejected` | SES Sandbox | 발신·수신 이메일 Verify |
| 이미지 403 | CDN 없이 S3 URL 사용 | ECS에 `AWS_CDN_URL` 확인 |
| S3 `AccessDenied` | IAM/버킷명 불일치 | `coupang-eats-{env}-storage` 권한 확인 |
