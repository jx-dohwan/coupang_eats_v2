## 💳 [Phase 3] Payment & Review System (Lifecycle Completion)

주문(Order) 이후의 프로세스를 처리하는 단계입니다. **결제(Payment)**를 통해 거래를 확정하고, 배달이 완료된 후 **리뷰(Review)**를 통해 피드백을 수집하며, **스케줄러(Cron)**를 통해 시스템을 유지 보수하는 로직이 구현되었습니다.

### 1. 주요 기능 (Key Implementations)

#### 💸 결제 검증 및 저장 (Payment Verification)
실제 PG사(Payment Gateway) 연동을 가정한 결제 처리 모듈입니다.
* **1:1 관계 매핑**: 하나의 주문(`Order`)에는 오직 하나의 결제(`Payment`)만 존재해야 합니다.
* **이중 결제 방지**: 이미 결제 내역이 존재하는 주문에 대해 추가 결제를 시도할 경우 예외를 발생시켜 데이터 정합성을 유지합니다.
* **소유권 검증**: 주문 당사자(Customer)만이 해당 주문에 대한 결제를 진행할 수 있습니다.

#### ⭐ 리뷰 작성 자격 제어 (Review Constraints)
리뷰 시스템의 신뢰도를 위해 엄격한 **작성 자격 검증 로직**을 적용했습니다. 아무나 리뷰를 쓸 수 없으며, 다음 조건을 모두 만족해야 합니다.
1.  **본인 확인**: 해당 주문을 생성한 고객(`Customer`)인가?
2.  **대상 일치**: 리뷰하려는 식당이 주문한 식당과 일치하는가?
3.  **상태 제어 (핵심)**: 주문 상태가 **`Delivered` (배달 완료)**인가?
    * *Pending, Cooking, PickedUp 상태에서는 리뷰 작성이 불가능합니다.*

#### 🕰️ 데이터 유지보수 자동화 (Cron Scheduling)
`@nestjs/schedule`을 도입하여 배치 작업을 자동화했습니다.
* **좀비 데이터 정리**: 주문이 생성되었으나 결제되지 않고 방치된(`Pending`) 주문들이 DB 용량을 차지하는 것을 방지합니다.
* **실행 주기**: 트래픽이 적은 **매일 새벽 04:00**에 실행됩니다.
* **삭제 기준**: 생성된 지 **24시간**이 지난 Pending 상태의 주문을 영구 삭제(Hard Delete)합니다.

### 2. API Endpoints

#### 💳 Payment (결제)
| Method | URI | Auth | Description |
| :--- | :--- | :--- | :--- |
| `POST` | `/payments` | **Client** | PG사 거래 ID(`transactionId`)를 받아 주문 결제 처리 |

#### 📝 Review (리뷰)
| Method | URI | Auth | Description |
| :--- | :--- | :--- | :--- |
| `POST` | `/reviews` | **Client** | 배달 완료된 주문에 대해 평점(1~5)과 리뷰 작성 |

### 3. 주요 로직 상세 (Code Highlights)

#### 리뷰 작성 자격 검증 (Review Guard Logic)
단순한 데이터 생성이 아니라, 비즈니스 흐름(Flow)상 올바른 타이밍인지 검사합니다.

```typescript
// ReviewService.createReview()
if (order.status !== OrderStatus.Delivered) {
  // 아직 배달 중이거나 조리 중인 경우 차단
  throw new BadRequestException('You can only review after delivery is complete.');
}
```

#### 스케줄러 설정 (Cron Job)
`TypeORM`의 `LessThan` 연산자를 활용하여 오래된 데이터를 효율적으로 탐색하고 정리합니다.

```typescript
@Cron(CronExpression.EVERY_DAY_AT_4AM)
async handleCron() {
  // 어제 날짜 계산
  const yesterday = new Date();
  yesterday.setDate(yesterday.getDate() - 1);

  // 조건: 상태가 Pending 이면서 && 생성일이 어제보다 이전인 데이터
  await this.orderRepository.delete({
    status: OrderStatus.Pending,
    createdAt: LessThan(yesterday),
  });
}
```

### 4. Database Schema Update

* **Payment Table**
    * `transactionId`: PG사 거래 고유 번호
    * `orderId`: 1:1 관계 (Unique Key)
    * `restaurantId`, `userId`: 빠른 조회를 위한 비정규화(Denormalization) 혹은 관계 설정

* **Review Table**
    * `score`: 1~5점 정수
    * `reviewText`: 리뷰 내용
    * `client`: 작성자 (User FK)
    * `restaurant`: 대상 식당 (Restaurant FK) - *`Order` 테이블을 거치지 않고 식당 리뷰를 빠르게 조회하기 위해 직접 연결*
