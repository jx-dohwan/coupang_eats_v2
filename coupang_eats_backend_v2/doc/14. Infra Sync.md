# 14. Infra Sync — 백엔드 ↔ coupang-eats-infra 맞춤

> 작성일: 2026-08-08  
> 대상 인프라: `coupang-eats-infra` v2 (ECS Fargate, Aurora MySQL, CloudFront OAC, ALB `/health`)

인프라를 업그레이드하면서 **백엔드가 깨지거나 unhealthy가 되지 않도록** 맞춘 변경 기록입니다.

---

## 왜 백엔드를 고쳤나

| 인프라 변경 | 백엔드가 안 맞으면 |
|-------------|-------------------|
| ALB health = `GET /health` | 태스크 Unhealthy → 트래픽 차단 |
| S3 퍼블릭 차단 + CloudFront OAC | 업로드는 되는데 **이미지 URL 403** |
| Aurora MySQL | 프로토콜은 MySQL 동일 (호환 OK) |
| Redis TLS | 이미 비-localhost면 `tls: {}` — OK |
| HTTPS / BASE_URL | Refresh 쿠키 `secure: false`면 브라우저가 쿠키 거부 가능 |

---

## 변경 목록 (What / How)

### 1. `GET /health` 추가

**파일:** `src/app.controller.ts`

| Before | After |
|--------|--------|
| `GET /` 만 `'OK'` 반환 | `GET /health` → `{ "status": "ok" }` |
| | `GET /` 유지 (하위 호환, Swagger 제외) |

- `@Public()` — JWT Guard가 ALB를 막지 않음  
- ALB Target Group `health_check_path = "/health"` 와 일치

---

### 2. CloudFront CDN URL (`AWS_CDN_URL`)

**파일:**
- `src/core/config/index.ts` — `AwsConfig.CDN_URL`
- `src/core/config/configuration.ts` — `process.env.AWS_CDN_URL`
- `src/core/aws/aws-s3.service.ts` — `buildPublicUrl()`

| Before | After |
|--------|--------|
| `https://{bucket}.s3.{region}.amazonaws.com/{key}` | `CDN_URL` 있으면 `https://{cdn}/{key}` |
| | 없으면 기존 S3 URL (로컬 fallback) |

ECS Task Definition이 주입하는 `AWS_CDN_URL` (= Terraform `module.storage.cdn_url`)을 사용합니다.

---

### 3. DB 포트 기본값

**파일:** `src/core/config/configuration.ts`

| Before | After |
|--------|--------|
| `DB_PORT` default `5432` (Postgres 잔재) | **`3306`** (MySQL / Aurora) |

---

### 4. Refresh 쿠키 `secure`

**파일:** `src/modules/auth/auth.controller.ts`

| Before | After |
|--------|--------|
| 항상 `secure: false` | `BASE_URL`이 `https://` 일 때만 `secure: true` (HTTP ALB에서는 false) |

ACM으로 HTTPS를 켠 뒤에도 쿠키가 동작하도록 맞춤.

---

### 5. Migration DataSource (ECS 친화)

**파일:** `src/data-source.ts`

| Before | After |
|--------|--------|
| 항상 `.env.local` 로드 + console.log | 파일이 있을 때만 dotenv 로드 |
| | ECS는 Task env만 사용, 디버그 로그 제거 |

Docker 이미지 `migration:run` → `start:prod` 경로와 맞춤.

---

### 6. SES 엔드포인트

**파일:** `src/core/aws/aws-ses.service.ts`

| Before | After |
|--------|--------|
| 하드코딩 `email.ap-northeast-2...` | `email.${AWS_REGION}.amazonaws.com` |

---

## ECS 환경 변수 매핑

인프라(`modules/compute`)가 넣는 값과 백엔드 읽기 위치:

| Env | 백엔드 | 비고 |
|-----|--------|------|
| `NODE_ENV` | `APP.NODE_ENV` / `ENV` | `dev` / `prod` |
| `PORT` | `APP.PORT` | `3000` |
| `BASE_URL` | `APP.BASE_URL` | ALB URL (http/https) |
| `DB_HOST` | `DB.DB_HOST` | Aurora Writer host |
| `DB_PORT` | `DB.DB_PORT` | `3306` |
| `DB_USER_NAME` | `DB.DB_USER_NAME` | `admin` |
| `DB_DATABASE` | `DB.DB_DATABASE` | `coupangeats` |
| `DB_PASSWORD` | Secrets Manager | ECS secrets |
| `REDIS_HOST` | `REDIS.HOST` | TLS on |
| `JWT_*` | `JWT.*` | SSM SecureString |
| `AWS_REGION` | `AWS.REGION` | |
| `AWS_S3_BUCKET_NAME` | `AWS.S3_BUCKET_NAME` | `coupang-eats-{env}-storage` |
| `AWS_CDN_URL` | `AWS.CDN_URL` | **신규** |
| `AWS_SES_SENDER_EMAIL` | `AWS.SES_SENDER_EMAIL` | |

로컬 예제: `dotenv/.env.example`

## 수정하지 않은 것 (이미 맞음 / 후속)

- Redis TLS (`cache.module.ts` 비-localhost → `tls: {}`) — 유지  
- CI가 EKS 경로인 부분 — 별도 작업 (`deploy-ecs.yml` 정리 권장)  
- Terminus 기반 DB/Redis deep health — 선택 사항 (ALB는 HTTP 200만 필요)
